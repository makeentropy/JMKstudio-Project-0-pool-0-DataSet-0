# 经验数据池与自反思智能体系统 - 产品需求文档

## Overview
- **Summary**: 构建一个经验数据沉积池（Experience Data Pool）系统，配合自反思智能体（Introspective Agent）和维度空间探针（Dimension Space Probe），实现智能体执行经验的自动采集、沉淀、分析、反省与自迭代优化。系统在现有 ai_llm_agent_crawler 项目基础上扩展，整合 dataset、dimension、storage、versioning 模块，形成完整的"经验采集 → 沉积存储 → 自省分析 → 迭代优化"闭环。
- **Purpose**: 解决智能体无法从历史经验中学习、技能迭代依赖人工反馈、数据质量洞察不足的问题。通过建立经验数据池和自反省机制，让智能体能像人类一样"总结经验、吸取教训、自我进化"。
- **Target Users**: AI 应用开发者、数据科学家、研究人员、需要构建自进化智能体系统的工程团队。

## Goals
- 建立经验数据 POOL，支持智能体运行经验的结构化沉积与镜像快照管理
- 实现自反思智能体，具备自我评估、错误归因、经验总结的自省能力
- 构建维度空间探针，可对数据维度空间进行探测、可视化与奇点定位
- 打通技能自迭代闭环：经验 → 反省 → 优化方案 → 技能更新 → 验证
- 提供经验分析工具集，支持多维度查询、趋势分析、模式挖掘

## Non-Goals (Out of Scope)
- 不实现强人工智能或真正的"自主意识"，仅为基于规则和统计的反省机制
- 不涉及物理世界的量子力学实验或引力模拟，仅为数据维度空间的隐喻性建模
- 不构建独立的 LLM 训练框架，仅生成可用于外部训练的经验数据集
- 不替换现有的 crawler、dataset、security 等模块，而是在其基础上扩展
- 不实现 GUI 界面，仅提供 Python API 和命令行工具

## Background & Context
- 现有项目 `ai_llm_agent_crawler` 已具备：数据集生成（dataset）、维度分类与奇点检测（dimension）、NAS 存储池（storage/pool.py）、Skill 生成与优化（skill_engine.py, skill_optimizer.py）、版本管理（versioning）等模块
- 现有 SkillOptimizer 已有基础的反馈收集和参数优化能力，但缺乏系统性的经验沉淀和深度自省机制
- 现有 dimension 模块已实现质量评估、奇点检测、质能模型等，可扩展为维度空间探针
- 现有 storage/pool.py 和 versioning/ 模块可复用于经验数据池的存储和快照管理

## Functional Requirements

### FR-1: 经验数据池 (Experience Data Pool)
系统应提供结构化的智能体经验数据存储与管理能力。
- 支持多种经验类型采集：任务执行记录、成功/失败案例、错误日志、性能指标、决策轨迹
- 经验数据自动沉积到 NAS 存储池，按时间/类型/质量分维度组织
- 支持经验数据的镜像快照（snapshot），可创建、对比、回滚经验池版本
- 提供经验数据的索引、查询、过滤、导出接口
- 支持经验数据质量评分与自动清洗（去重、降噪、标记低质量经验）

### FR-2: 自反思智能体 (Introspective Agent)
系统应具备自我反省、自我分析的能力。
- 自省触发：任务完成后自动触发反省，或手动触发深度反省
- 自我评估：对自身任务表现进行多维度评分（准确性、效率、完整性、创新性）
- 错误归因：分析失败案例的根本原因，归类为数据问题、策略问题、参数问题等
- 经验总结：从成功/失败案例中提炼可复用的经验模式（heuristics）
- 自我认知：维护智能体的"能力画像"，记录擅长领域、薄弱环节、知识边界

### FR-3: 维度空间探针 (Dimension Space Probe)
系统应提供对数据维度空间的探测与分析能力。
- 多维探测：对数据集在质量、结构、内容、统计、关系等维度上进行深度探测
- 路径探测：可沿着指定维度方向进行"探针式"深度扫描，发现隐藏模式
- 奇点定位：精确定位质能奇点、维度坍缩点、量子纠缠点等异常区域
- 空间可视化：生成维度空间的拓扑描述、密度分布、距离矩阵
- 探针报告：输出结构化的探测报告，包含发现的问题、风险、优化建议

### FR-4: 技能自迭代闭环 (Skill Self-Iteration Loop)
系统应实现基于经验反省的技能自动优化闭环。
- 优化触发：当反省发现性能下降或积累足够经验时自动触发优化
- 策略生成：基于反省分析结果生成具体的技能优化策略（规则调优/参数调整/代码改进）
- 版本验证：优化后的技能自动运行测试，对比新旧版本性能
- 渐进部署：支持灰度发布、A/B 测试、自动回滚
- 迭代记录：完整记录每一次迭代的原因、变更、效果，形成进化轨迹

### FR-5: 经验分析工具集 (Experience Analytics Toolkit)
系统应提供多维度的经验数据分析工具。
- 趋势分析：智能体能力随时间的变化趋势
- 模式挖掘：从历史经验中发现高频成功模式和常见失败模式
- 对比分析：不同版本、不同任务类型、不同策略之间的效果对比
- 预测预估：基于历史经验预测未来任务的成功率和资源需求
- 经验导出：支持将经验池导出为标准训练数据集格式

## Non-Functional Requirements

- **NFR-1**: 性能 - 单次反省分析（1000条经验以内）应在 10 秒内完成；探针扫描 10 万条数据应在 60 秒内完成
- **NFR-2**: 可扩展性 - 经验池存储应支持水平扩展，单节点可处理百万级经验记录
- **NFR-3**: 数据安全 - 敏感经验数据支持加密存储（复用现有 security 模块），访问需鉴权
- **NFR-4**: 兼容性 - 完全兼容现有 ai_llm_agent_crawler 的 API 和数据格式
- **NFR-5**: 可观测性 - 提供详细的自省日志、探针轨迹、迭代指标，支持调试和审计
- **NFR-6**: 容错性 - 反省或优化失败不应影响智能体正常运行，支持降级模式

## Constraints

- **Technical**: Python 3.9+，基于现有项目架构扩展，使用 pydantic 进行数据建模，pandas/numpy 进行数据处理
- **Business**: 以现有项目模块为基础，增量开发，不破坏现有功能
- **Dependencies**: 复用现有 dataset、dimension、storage、versioning、security 模块；可能需要 scikit-learn（聚类/降维）、networkx（图分析）

## Assumptions

- 用户理解"维度空间""质能奇点""量子纠缠"等术语在本项目中为数据科学的隐喻性建模，而非物理学概念
- 经验数据池以结构化数据（DataFrame/JSON）为主，不处理非结构化的视频/音频数据
- 自反思机制基于规则和统计分析，不依赖外部大语言模型进行自省推理（但可配置接入）
- 现有 NAS 存储池和版本管理模块可直接复用于经验数据的存储和快照

## Acceptance Criteria

### AC-1: 经验数据沉积与存储
- **Given**: 智能体执行任务产生执行记录、性能指标、错误日志等数据
- **When**: 任务执行完成后，系统自动将经验数据写入经验池
- **Then**: 经验数据被结构化存储，包含唯一ID、时间戳、任务类型、结果状态、性能指标等字段；可通过任务ID、时间范围、类型等条件查询检索
- **Verification**: `programmatic`
- **Notes**: 经验记录需包含至少 10 个标准字段，查询响应时间 < 1s

### AC-2: 经验池快照管理
- **Given**: 经验池中已积累一定数量的经验数据
- **When**: 用户触发创建快照操作，或达到预设的快照周期
- **Then**: 系统创建当前经验池的完整镜像快照，分配版本号，支持与历史快照对比差异，支持回滚到指定快照
- **Verification**: `programmatic`
- **Notes**: 复用现有 versioning 模块，快照创建时间与数据量成线性关系

### AC-3: 智能体自我评估
- **Given**: 智能体完成一个任务，有执行结果和参考标准
- **When**: 触发自省流程中的自我评估阶段
- **Then**: 系统输出多维度评分（准确性、效率、完整性、资源使用率），每个维度 0-1 分，附评分依据说明
- **Verification**: `programmatic`
- **Notes**: 评分算法需可配置，支持自定义评估维度

### AC-4: 错误归因分析
- **Given**: 任务执行失败或结果低于阈值
- **When**: 自省流程进行错误归因
- **Then**: 系统输出失败原因分类（数据问题/策略问题/参数问题/环境问题/未知），附置信度和关键证据
- **Verification**: `programmatic`
- **Notes**: 至少支持 5 种错误分类，置信度基于规则和历史相似案例计算

### AC-5: 维度空间探针探测
- **Given**: 一个待分析的数据集
- **When**: 调用维度空间探针对数据集进行全面探测
- **Then**: 输出结构化探测报告，涵盖质量维度、结构维度、统计维度、内容维度、关系维度的分析结果，标记发现的奇点和异常
- **Verification**: `programmatic`
- **Notes**: 报告包含至少 5 个维度的分析，每个维度有量化指标和定性描述

### AC-6: 深度路径探测
- **Given**: 指定一个数据集和某个特定维度方向
- **When**: 探针沿着指定维度进行深度扫描
- **Then**: 输出该维度方向上的数据分布、密度变化、临界点位置、异常区域坐标
- **Verification**: `programmatic`
- **Notes**: 支持自定义探测步长和深度

### AC-7: 技能自动优化闭环
- **Given**: 一个已注册的 Skill，且积累了足够的反馈经验
- **When**: 触发技能自迭代优化
- **Then**: 系统自动分析经验 → 生成优化方案 → 生成新版本 Skill → 运行测试验证 → 若性能提升则自动应用；完整记录迭代过程
- **Verification**: `programmatic`
- **Notes**: 优化前后性能对比可量化，支持自动回滚

### AC-8: 经验趋势分析
- **Given**: 经验池中有足够的历史数据（至少 10 个时间点）
- **When**: 请求经验趋势分析
- **Then**: 输出智能体能力随时间的变化趋势，包括整体能力曲线、各维度趋势、关键拐点标注
- **Verification**: `human-judgment`
- **Notes**: 趋势图需清晰可读，拐点标注有解释说明

### AC-9: 经验模式挖掘
- **Given**: 经验池中有大量历史案例
- **When**: 执行经验模式挖掘
- **Then**: 系统识别出高频成功模式和常见失败模式，每种模式附出现频率、典型特征、适用场景
- **Verification**: `human-judgment`
- **Notes**: 至少挖掘出 3 种以上有意义的模式

### AC-10: 自我认知画像
- **Given**: 智能体有一定历史经验
- **When**: 查询智能体自我认知画像
- **Then**: 返回智能体的能力画像：擅长领域、薄弱环节、知识边界、典型错误类型、改进方向
- **Verification**: `human-judgment`
- **Notes**: 画像基于历史经验数据生成，而非静态配置
