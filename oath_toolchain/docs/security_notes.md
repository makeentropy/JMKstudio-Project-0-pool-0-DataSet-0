## 密码学安全说明

### 1. 对称加密

#### AES-GCM

神誓工具链使用 AES-GCM 模式进行对称加密，这是一种认证加密模式，同时提供机密性和完整性保护。

**安全特性**:
- 使用 128 位随机 nonce（Number used Once）
- 提供认证标签（16 字节 GCM tag）
- 支持 128、192、256 位密钥

**注意事项**:
- 切勿使用相同的密钥和 nonce 加密不同的消息
- GCM 模式对 nonce 重用非常敏感，可能导致密钥泄露
- 建议每次加密都使用新的随机 nonce

### 2. 非对称加密

#### RSA-OAEP

使用 RSA-OAEP（Optimal Asymmetric Encryption Padding）进行非对称加密。

**安全特性**:
- 使用 OAEP 填充方案，比传统 PKCS#1 v1.5 更安全
- 基于 SHA-256 哈希函数
- 支持 2048、3072、4096 位密钥

**建议**:
- 生产环境建议使用至少 2048 位密钥
- 长期安全建议使用 4096 位密钥
- RSA 加密适合加密小数据（如对称密钥），不适合加密大量数据

### 3. 哈希算法

支持的哈希算法及其安全性级别：

| 算法 | 输出长度 | 安全级别 | 推荐用途 |
|------|----------|----------|----------|
| SHA-256 | 256 位 | 高 | 通用哈希、数字签名 |
| SHA-512 | 512 位 | 很高 | 高安全需求场景 |
| SHA3-256 | 256 位 | 高 | SHA-3 标准 |
| SHA3-512 | 512 位 | 很高 | SHA-3 高安全需求 |
| BLAKE2b | 512 位 | 很高 | 高性能哈希 |
| BLAKE2s | 256 位 | 高 | 轻量级哈希 |
| MD5 | 128 位 | **不安全** | 仅用于向后兼容 |

**警告**: MD5 已被破解，**绝对不要**用于安全相关的场景。

### 4. 密钥派生

#### PBKDF2-HMAC-SHA256

从密码派生密钥时使用 PBKDF2-HMAC-SHA256。

**参数建议**:
- 迭代次数：至少 100,000 次（默认值）
- 盐值：使用 16 字节以上的随机盐
- 输出长度：根据需要选择，通常 32 字节

**注意**:
- 迭代次数越多越安全，但速度越慢
- 盐值应该随机生成并与派生密钥一起存储

### 5. HMAC

使用 HMAC（Hash-based Message Authentication Code）进行消息认证。

**安全特性**:
- 支持多种哈希算法
- 提供消息完整性和认证
- 抗碰撞攻击

**建议**:
- 使用至少 32 字节的密钥
- 密钥应该是随机生成的，不是密码

## 使用最佳实践

### 密钥管理

#### 1. 密钥生成

```python
# ✅ 好的做法：使用加密安全的随机数生成器
key = sdk.keys.generate_aes_key(256)

# ❌ 不好的做法：使用可预测的密钥
key = b"1234567890123456"  # 不要这样做！
```

#### 2. 密钥存储

- **不要**将密钥硬编码在代码中
- **不要**将密钥提交到版本控制系统
- 使用环境变量、密钥管理服务或加密配置文件存储密钥
- 定期轮换密钥

```python
# ✅ 好的做法：从环境变量读取密钥
import os
key = os.environ.get("ENCRYPTION_KEY")
if not key:
    raise ValueError("ENCRYPTION_KEY 环境变量未设置")

# ❌ 不好的做法：硬编码密钥
key = b"my-secret-key-123"  # 绝对不要这样做！
```

#### 3. 密钥传输

- 不要通过不安全的通道传输密钥
- 使用 RSA 或其他非对称加密方式交换对称密钥
- 使用密钥协商协议（如 ECDH）

### 加密实践

#### 1. 选择合适的加密算法

- 对称加密大数据：使用 AES-GCM
- 非对称加密小数据：使用 RSA-OAEP
- 混合加密：用 RSA 加密 AES 密钥，用 AES 加密数据

```python
# 推荐的混合加密方案
aes_key = sdk.keys.generate_aes_key(256)
encrypted_data = sdk.crypto.encrypt_aes(large_data, aes_key)
encrypted_key = sdk.crypto.encrypt_rsa(aes_key, rsa_public_key)
# 存储/传输 encrypted_data 和 encrypted_key
```

#### 2. 认证数据

- 所有加密都应该包含完整性验证
- 使用 AES-GCM（已包含认证）
- 或使用 Encrypt-then-MAC 模式

#### 3. Nonce 管理

- 每次加密使用新的随机 nonce
- 不要重用 nonce
- nonce 不需要保密，但必须唯一

### 签名验证

- 使用签名验证数据的来源和完整性
- 验证签名时使用可信的公钥
- 检查证书链和证书有效期

### 隐写术使用

#### 适用场景

- 隐蔽通信
- 数字水印
- 数据防篡改检测

#### 注意事项

- 隐写术不能替代加密
- 高安全性场景应先加密再隐写
- 注意载体容量限制
- 评估隐写的可检测性

## 安全警告

### ⚠️ 重要警告

#### 1. 这不是经过审计的密码学库

神誓工具链是一个开源项目，**没有经过专业的密码学安全审计**。

- 不要用于保护高度敏感的数据
- 不要用于生产环境的关键安全系统
- 建议在生产环境使用经过审计的标准库（如 cryptography、OpenSSL）

#### 2. 自定义加密算法

项目中的 KARMACA 空间加密、几何证明等是实验性算法：

- 这些算法**没有经过广泛的密码分析**
- 安全性可能不如标准算法
- 仅用于学习和研究目的
- 敏感数据请使用 AES、RSA 等标准算法

#### 3. NLP 密钥生成

从自然语言生成密钥时请注意：

- 密钥强度取决于输入文本的熵值
- 常见短语或句子生成的密钥强度较低
- 不要使用著名的诗句、名言作为密钥源
- 高安全场景请使用随机生成的密钥

#### 4. 隐写术的局限性

隐写术不是万无一失的：

- 高级隐写分析技术可能检测到隐写数据
- 不要依赖隐写术保护高度敏感信息
- 建议先加密再隐写（双重保护）

### 已知安全问题

#### 1. MD5 算法

- MD5 已被证明不安全，存在碰撞攻击
- 仅为兼容性而保留
- **不要**用于任何安全相关的用途

#### 2. 小密钥尺寸

- 128 位 AES 密钥在某些场景下可能不够
- RSA 1024 位已被认为不安全
- 建议使用至少 256 位 AES 和 2048 位 RSA

## 已知限制

### 1. 性能限制

- 纯 Python 实现的加密算法速度较慢
- 大数据量加密建议使用硬件加速的库
- RSA 密钥生成（特别是大密钥）可能很慢

### 2. 算法覆盖

- 不支持椭圆曲线加密（ECC）
- 不支持后量子密码学
- 不支持 AEAD 模式（除了 GCM）

### 3. 平台兼容性

- 依赖 `cryptography` 库，需要正确安装
- 某些平台可能需要额外的系统依赖
- Windows 平台可能需要 Visual C++ Redistributable

### 4. 测试覆盖

- 虽然测试覆盖率达 89.6%，但不能保证没有 bug
- 某些边缘情况可能未被测试覆盖
- 密码学代码的正确性很难完全验证
