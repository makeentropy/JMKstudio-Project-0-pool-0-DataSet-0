## 总体架构

神誓工具链采用四层分层架构设计，从上到下依次为：

```
┌─────────────────────────────────────────────────────┐
│                   接口层 (Interface)                 │
│         SDK API        CLI        REST API          │
├─────────────────────────────────────────────────────┤
│                 编排层 (Orchestration)               │
│    乾坤引擎    管道系统    工作流执行器  安全编排器   │
├─────────────────────────────────────────────────────┤
│                    工具层 (Tools)                    │
│  KARMACA  几何证明  CA证书  隐写术  NLP密钥  奇点   │
│  数据集池  Karma标签                                 │
├─────────────────────────────────────────────────────┤
│                    核心层 (Core)                     │
│  密码原语  数据结构  数学基础  工具基类  配置管理    │
│  异常体系  日志工具  注册表                          │
└─────────────────────────────────────────────────────┘
```

### 设计原则

1. **分层清晰**：每一层只依赖其下方的层，不允许向上依赖
2. **高内聚低耦合**：同一层内的模块高度相关，层间通过明确的接口交互
3. **可扩展性**：各层均支持插件式扩展，方便添加新功能
4. **统一接口**：通过 SDK 和 CLI 提供一致的用户体验

## 接口层

接口层是用户与系统交互的入口，提供多种访问方式。

### 主要组件

#### 1. SDK API

**位置**: `src/oath_toolchain/sdk/`

**核心类**:
- `OathSDK`：SDK 主入口类，统一管理所有子 API
- `CryptoAPI`：加密相关 API
- `KeyAPI`：密钥管理 API
- `CAAPI`：CA 证书体系 API
- `StegoAPI`：隐写术 API
- `DatasetAPI`：数据集管理 API
- `PipelineAPI`：管道编排 API

**职责**:
- 提供高层、易用的编程接口
- 封装底层实现细节
- 统一错误处理和参数验证
- 管理工具实例生命周期

#### 2. CLI 命令行

**位置**: `src/oath_toolchain/cli/`

**核心模块**:
- `main.py`：CLI 主入口
- `commands/keygen.py`：密钥生成命令
- `commands/encrypt.py`：加密命令
- `commands/decrypt.py`：解密命令
- `commands/sign.py`：签名命令
- `commands/verify.py`：验证命令
- `commands/ca.py`：CA 证书命令
- `commands/stego.py`：隐写命令
- `commands/pipeline.py`：管道命令
- `commands/dataset.py`：数据集命令
- `commands/tool.py`：工具管理命令

**职责**:
- 提供命令行交互接口
- 解析命令行参数
- 调用 SDK 执行操作
- 格式化输出结果

#### 3. REST API（预留）

预留 REST API 接口，未来可通过 HTTP 方式访问。

## 编排层

编排层负责工具的注册管理、管道执行和工作流编排，是连接接口层和工具层的桥梁。

### 主要组件

#### 1. 乾坤引擎 (QiankunEngine)

**位置**: `src/oath_toolchain/orchestration/qiankun_engine.py`

**核心功能**:
- 工具注册与发现
- 管道管理
- 工作流管理
- 安全上下文管理

**关键方法**:
- `register_tool(tool)`：注册工具
- `get_tool(tool_name)`：获取工具实例
- `create_pipeline(name, steps)`：创建管道
- `execute_pipeline(name, input_data)`：执行管道
- `create_workflow(name, definition)`：创建工作流
- `execute_workflow(name, input_data)`：执行工作流

#### 2. 管道系统 (Pipeline)

**位置**: `src/oath_toolchain/orchestration/pipeline.py`

**核心类**:
- `Pipeline`：管道类，包含多个步骤
- `PipelineStep`：管道步骤类

**功能**:
- 定义多步处理流程
- 支持步骤间的数据传递
- 错误处理和回滚

#### 3. 工作流执行器 (WorkflowExecutor)

**位置**: `src/oath_toolchain/orchestration/workflow_executor.py`

**功能**:
- 解析工作流定义
- 按依赖关系执行任务
- 支持条件分支和循环
- 工作流状态管理

#### 4. 安全编排器 (SecurityOrchestrator)

**位置**: `src/oath_toolchain/orchestration/security_orchestrator.py`

**功能**:
- 安全策略管理
- 安全配置文件管理
- 安全审计日志
- 访问控制

## 工具层

工具层包含8大功能模块，每个模块都是相对独立的工具，提供特定的安全功能。

### 工具模块列表

| 模块 | 位置 | 功能描述 |
|------|------|----------|
| KARMACA 空间字典 | `tools/karmaca/` | 基于多维空间映射的加密系统 |
| 几何证明 | `tools/geometric_proof/` | 几何哈希、零知识证明、VRF |
| CA 证书体系 | `tools/ca_system/` | 完整的 PKI 证书管理系统 |
| 隐写术 | `tools/steganography/` | XOR、文本、证书隐写 |
| NLP 密钥生成 | `tools/nlptcmodel/` | 从自然语言生成密钥 |
| 奇点验证 | `tools/singularity/` | 密钥和数据的奇点检测 |
| 数据集池 | `tools/dataset_pool/` | 带版本控制的数据集管理 |
| Karma 标签 | `tools/karma_tags/` | Karma 标签索引和签名 |

### 工具基类

所有工具都继承自 `OathTool` 基类，位于 `core/base.py`。

**统一接口**:
- `name`：工具名称
- `description`：工具描述
- `execute(params)`：执行工具操作
- `validate_params(params)`：验证参数

**工具注册**:
- 使用 `@register_tool` 装饰器注册
- 注册到全局 `ToolRegistry`

## 核心层

核心层提供基础的密码原语、数据结构、数学工具和通用基础设施。

### 主要模块

#### 1. 密码原语 (crypto)

**位置**: `src/oath_toolchain/core/crypto/`

**模块**:
- `primitives.py`：AES、RSA 等基础加密算法
- `hash.py`：各种哈希算法
- `kdf.py`：密钥派生函数
- `random.py`：随机数生成

#### 2. 数据结构 (data_structures)

**位置**: `src/oath_toolchain/core/data_structures/`

**模块**:
- `hash_chain.py`：哈希链
- `merkle.py`：默克尔树

#### 3. 数学基础 (math)

**位置**: `src/oath_toolchain/core/math/`

**模块**:
- `vector.py`：向量运算
- `space.py`：空间运算

#### 4. 通用基础设施

**位置**: `src/oath_toolchain/core/`

**模块**:
- `base.py`：工具基类
- `config.py`：配置管理
- `exceptions.py`：异常体系
- `logging_util.py`：日志工具
- `registry.py`：工具注册表

### 跨模块调用规则

1. **只能向下调用**：上层模块可以调用下层模块，反之则不行
2. **同层调用需谨慎**：同一层内的模块可以互相调用，但应避免循环依赖
3. **通过接口调用**：模块间应通过公开接口交互，不直接访问内部实现
4. **依赖注入**：通过乾坤引擎管理工具实例，实现松耦合
